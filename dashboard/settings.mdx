The **Settings** module is SUITEe's central configuration hub for hotel operations, hardware connectivity, and administrative permissions. From here, hotel managers configure their property's public identity, synchronize operational timelines with their Property Management System (PMS), provide guest communication channels, and connect IoT gateway hardware.

Access the property settings at:

```
https://hotel.suite-e.com/settings/property-account
```

---

</Frame>

### Sub-navigation tabs

The **E-Mail (SMTP)** configuration header offers two operational tabs:

1. **`SMTP-Konfiguration`**: Manages outbound email dispatch methods, sender identities, and SMTP server credentials.
2. **`Test-E-Mail senden`**: Allows administrators to dispatch a live test message to verify server connectivity, authentication, and deliverability before putting settings live.

---

### Email dispatch options (`Versand der E-Mails`)

The **Versand der E-Mails** card controls whether automated emails are delivered via SUITEe's built-in cloud email service or routed through your hotel's custom corporate mail server.

It provides two mutually exclusive checkbox options:

| Option | Mode | Editing Status | Description |
| :--- | :--- | :---: | :--- |
| **`Standard-Suite *`** | Built-in Cloud Relay | **Locked / Read-Only** | Uses SUITEe's managed cloud delivery infrastructure. All email and server fields below are automatically disabled and locked from editing. |
| **`Eigenen SMTP verwenden`** | Custom Hotel Mail Server | **Unlocked / Fully Editable** | Unlocks all email sender details, CC recipients, and SMTP server credentials for custom configuration. |

---

### Option 1 — Managed delivery (`Standard-Suite *`)

When **`Standard-Suite *`** is selected (indicated by an orange checked box):

<Frame>
  <img src="/images/settings-smtp-standard-suite.png" alt="Email settings with Standard-Suite enabled showing read-only locked fields in E-Mail-Informationen and SMTP sections" />
</Frame>

#### Features & locked state
- **Zero Configuration Required**: SUITEe handles all outbound transactional messages out-of-the-box using pre-authenticated enterprise cloud relays.
- **Fields Disabled**: All input fields across **E-Mail-Informationen** (`Absender-E-Mail`, `Absendername`, `CC-Adressen`) and **SMTP** (`Port`, `Host`, `Verschlüsselung`, `Benutzername`, `Passwort`) are disabled and rendered in dark read-only state.
- **Optimized Deliverability**: Includes pre-configured SPF, DKIM, and DMARC alignment to ensure door unlock codes and check-in emails land reliably in guests' primary inboxes without being flagged as spam.
- **Recommended For**: Properties without dedicated IT administrators or custom corporate email servers.

### Sending a test email (`Test-E-Mail senden`)

To verify that your custom SMTP credentials or standard relay deliver messages properly without waiting for real guest bookings, switch to the **`Test-E-Mail senden`** tab at the top of the page:

<Frame>
  <img src="/images/settings-smtp-test-email.png" alt="Test-E-Mail senden tab showing recipient An field, Betreff subject field, HTML-Inhalt body textarea, and Test senden button" />
</Frame>

The test email utility allows administrators to execute a dry run of the outbound email pipeline:

| Field / Control | Required | Description |
| :--- | :---: | :--- |
| **`An *`** | Yes `*` | The recipient destination email address (e.g. `admin@hotel-savoy.com` or your personal inbox). Used to verify reception in a real mail client. |
| **`Betreff *`** | Yes `*` | The email subject line (e.g. *SUITEe SMTP Test Delivery*). |
| **`HTML-Inhalt *`** | Yes `*` | The body content of the test email. Supports both plain text and full HTML markup tags (e.g. `<h3>Testnachricht</h3><p>Verbindung erfolgreich.</p>`). |
| **`Test senden` Button** | — | Triggers an immediate test transmission through the active mail transport. |

#### Verification checklist during test dispatch

Clicking **`Test senden`** performs a comprehensive end-to-end verification of the mail transport:

1. **Network Connectivity**: Verifies TCP socket reachability to the specified mail host on port `587`, `465`, or `25`.
2. **Cryptographic Handshake**: Validates TLS/SSL certificate negotiation and encryption ciphers.
3. **Authentication Handshake**: Authenticates the provided username and password against the mail server.
4. **Sender Authorization**: Confirms that the `Absender-E-Mail` is permitted to send mail through the authenticated mailbox or relay.
5. **Inbox Reception**: Check your destination inbox to inspect email headers, verify DKIM/SPF alignment, and confirm layout rendering.

#### Troubleshooting diagnostic feedback

- **Success**: Displays a confirmation notification indicating that the SMTP server accepted the message for delivery (`250 2.0.0 OK`).
- **Connection Error**: If the host is unreachable or blocked by a firewall, the system reports the timeout error, prompting you to verify the hostname and port.
- **Authentication Failure**: If credentials are incorrect, the system reports standard SMTP response codes (e.g. `535 5.7.8 Authentication credentials invalid`), allowing quick correction without disturbing guest operations.

Selecting **Rollenverwaltung** under the **Zugangsverwaltung** heading in the left sub-sidebar opens the role-based access control (RBAC) management center. From here, administrators define custom staff roles, restrict sensitive configuration screens, and grant granular permissions across platform modules.

```
https://hotel.suite-e.com/settings/roles
```

---

### Toolbar controls and search

The toolbar directly above the roles table provides instant search and administrative actions:

- **Search Bar (`Suche` / `Rollen suchen`)**:
  - Located on the left with a magnifying glass icon and placeholder:
    ```
    Rollen suchen
    ```
  - **Live Querying**: Filters roles dynamically as keystrokes are entered across role names (e.g. `Front Desk Test`), descriptions, and module permissions.
  - **Case-Insensitive**: Matches search terms regardless of upper or lowercase lettering.
- **Refresh Button (`↻`)**: Re-queries the server database to synchronize role permissions and user assignments without requiring a full browser refresh.
- **Add Role Button (`+ Rolle hinzufügen`)**: Prominent orange call-to-action button that opens the **`Rolle erstellen`** modal dialog.

---

### Roles inventory table

The table catalogs all configured staff roles with their scope of authorization:

| Column | Sortable | Description |
| :--- | :---: | :--- |
| **Rollenname** | **`⇅`** | The public identifier of the role (e.g. `Front Desk Test`, `Property Admin`, `Housekeeping Lead`). Click column header arrows to sort alphabetically. |
| **Beschreibung** | — | A detailed description defining the role's operational scope, responsibilities, and restrictions (e.g. `Reception with no access to sensitive...`). |
| **Bereiche / Modulzugriff** | — | Badges displaying the authorized modules and functional capabilities assigned to this role. |
| **Erstellt von** | — | The team member or system administrator who authored the role (e.g. `Kallola Bal`). |
| **Erstellungsdatum** | **`⇅`** | The exact date when the role was created (e.g. `25 Aug 2026`). Click column header arrows to sort chronologically. |
| **Aktionen** | — | Three vertical dots menu (**`⋮`**) offering role management options. |

#### Authorized module badges (`Bereiche / Modulzugriff`)

Each badge chip represents an unlocked platform area:

- **`Zugangsverwaltung`**: Access management, issuing PIN codes, and encoding guest keycards.
- **`Buchungen`**: Reading and managing guest reservations, check-in statuses, and room allocation.
- **`Geräte`**: Smart device monitoring, lock diagnostics, and thermostat controls.
- **`E-Mail-Dienst`**: Viewing email templates and dispatch logs.
- **`Rollen & Berechtigungen`**: Permission assignment privileges.
- **`E-Mail (SMTP)`**: Access to outbound mail server configuration.

#### Table pagination controls

Located at the bottom of the table:
- **`Zeilen pro Seite: 10 ⌄`**: Dropdown selector allowing operators to choose display density (10, 25, 50 rows per page).
- **Record Counter**: Displays active viewing window and total entries (e.g. `1–1 of 1`).
- **Page Selector**: Displays `Gehe zu Seite: 1 von 1` with previous (`<`) and next (`>`) navigation controls.

#### Row actions menu (`⋮`)

Clicking the three vertical dots **`⋮`** on any role row opens options to:
- **Edit Role (`Bearbeiten`)**: Modify role name, description, or toggle module permissions.
- **Duplicate Role (`Duplizieren`)**: Clone an existing role template to create specialized variations (e.g. Daytime Reception vs. Night Auditor).
- **Delete Role (`Löschen`)**: Remove custom roles. (Protected: roles currently assigned to active team members cannot be deleted until users are reassigned).

## Interconnected dashboard modules

Settings configured across all four phases directly integrate with other SUITEe operational modules:

- **[Users & Teams](/dashboard/users-management)**: Team members assigned to properties inherit permission boundaries defined in Rollenverwaltung.
- **[Email Services](/dashboard/email-services)**: Automated guest journeys and notifications utilize the active transport configured in the SMTP-Manager.
- **[Rooms](/dashboard/rooms)**: Physical room inventories map directly into the vertical floor hierarchy configured in the Stockwerksplan.
- **[Access Management](/dashboard/access-management)**: Utilizes operational check-in/out times and IoT Store Code to schedule valid PIN codes and keycards.
- **[Smart Devices](/dashboard/devices)**: Communicates with door locks and climate controls through the assigned IoT hardware gateway, organized by building floor.
- **[Explore](/dashboard/explore)**: Anchors local partner business recommendations to the property's verified geographic address and coordinates.
